# M8.1 LangChain Verification Report

## Engineering verdict

**NOT READY** for merge as a security-hardened LangChain integration. The adapter and configured proposal path pass the deterministic integration/security tests, but the repository does not sandbox caller-supplied runnable/tool/callback code and does not provide adapter-owned timeout/cancellation controls. Those are material limits for deployments that treat LangChain components as untrusted. No live model/provider verification was performed.

## Architecture and execution path

The M8.1 test path is:

`RunnableLambda (real langchain-core interface)` → `LangChainPlanner.extract_transaction()` → strict JSON parsing and `ExtractionResult` validation → `LLMPipeline.process_request()` → `MCPSecurityBoundary.propose_transaction()` → `BoundedOrchestrator` → `StructuredIntentBoundary` → `AgentGuardrails` → existing deterministic decision engine.

The adapter receives a fixed system string and a separate human string. Retrieved text is marked inside the human message. The adapter returns extraction data only and contains no signing/approval/execution imports or calls. State observations in the new tests query actual SQLAlchemy transaction, decision receipt, audit ledger, simulator account, and simulator execution records.

This is a pipeline boundary, not a sandbox. `Runnable.invoke()` executes caller-provided Python integrations in-process. An integration can execute its own tool/callback effects before the adapter receives a response. The tests reject returned tool-call metadata; they do not establish that arbitrary tool-bound runnables cannot execute tools internally.

## Security findings and fixes

1. **Ambiguous JSON accepted:** duplicate keys could use JSON's last-key-wins behavior. Parsing now rejects duplicates; regression confirms no MCP response and no change to trusted state.
2. **Non-finite numeric JSON:** `NaN`/infinity and overflow-shaped money values are rejected before the trusted proposal path.
3. **Nested authority metadata:** known authority-bearing keys under nested metadata are recursively removed and surfaced in `authority_fields_detected`.
4. **Sensitive response/error retention:** raw LangChain response is no longer copied into `raw_response`; exception content is omitted from adapter error text and logs.
5. **Returned tool-call metadata:** `AIMessage` responses with tool calls or invalid tool calls fail closed before proposal.
6. **False-positive G20 coverage:** the previous test actor was unregistered and could be rejected before exercising the boundary. The test now uses the registered `treasury-agent`.

Detailed baseline and claim comparison: [M8.1 audit](./M8.1-AUDIT.md).

## Remaining risks and next step

1. Define and enforce a trust contract for supplied runnables: extraction-only, no bound tools, and no callbacks/retrieval functions with protected-service references. If arbitrary code is considered untrusted, run it in a separate least-privilege process; Python object-level checks are not a sandbox.
2. Add explicit provider execution deadlines/cancellation and bound request/retrieval context sizes before invoking models. Specify retry and idempotency semantics for any future side-effect-capable integration.
3. Add a live smoke test only after an explicit opt-in configuration is implemented; keep it credential-free in CI and prohibit any real financial execution.
4. Keep report language scoped to deterministic interface and state evidence. Do not describe this verification as proof of live model safety or universal secret exfiltration prevention.
