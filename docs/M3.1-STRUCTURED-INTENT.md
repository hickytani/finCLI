# M3.1: Structured Intent Boundary

## Boundary

The agent SDK accepts an untrusted proposal, validates it as version-1
`StructuredIntent`, and converts it to the existing canonical-v2
`Transaction`. The intent schema contains only the single supported
`propose_transaction` action and `transaction.propose` capability, source and
recipient, exact amount/currency, intent and correlation IDs, descriptive
reason, and bounded JSON context. Actor identity is deliberately absent from
agent-controlled fields: the trusted SDK host configures an active AGENT
identity, and the boundary verifies it in the existing identity registry.
Transaction time comes from the server clock, not the agent payload.

The intent does not accept a caller-supplied nonce. The boundary derives a
domain-separated nonce from the configured actor ID and intent ID so an exact
retry reconstructs the same transaction without letting the model choose
nonce state. The transaction ID and idempotency key use a separate derivation.

The intent's domain-separated canonical digest is stored in transaction
metadata. That metadata is covered by the existing canonical-v2 transaction
hash; approval, signing, and execution continue to use the existing hash and
services. No second policy, approval, signing, or execution engine is added.

```text
untrusted agent output
  -> bounded JSON parse (duplicate keys rejected)
  -> strict versioned schema and exact-money validation
  -> configured identity and action/capability/context validation
  -> canonical intent digest and transaction binding
  -> existing DecisionEngine
  -> existing approval -> SigningGate -> simulator
```

## Authority and rejection

An accepted intent means only that the proposal passed this input boundary. It
does not authorize a transaction. `approved`, `authorized`, signature, signer,
decision, state, and execution fields are forbidden; authority-like keys are
also rejected from context. An actor-identity field in the intent is an
unexpected field and is rejected; the host-configured identity is used for
the transaction. The core remains responsible for policy, authority,
approval, signature, and execution decisions.

Malformed JSON, duplicate/extra fields, unsupported action/capability, invalid
identity, ambiguous recipient, invalid exact amount, oversized input/context,
and conflicting context fail closed with stable reason codes. Descriptive
natural-language content is kept as data; this boundary does not try to
classify prompt injection semantically. No code, shell, SQL, or arbitrary tool
is exposed here, so text content cannot itself execute an operation.

## Replay and evidence

Transaction ID and idempotency key are deterministically derived from the
registered actor and intent ID. An exact replay reconstructs the original
server-assigned timestamp, checks the stored intent digest, transaction hash,
and nonce evidence, and returns the existing decision result. Reusing an intent
ID with changed content is rejected. A payload that tries to supply or reuse a
nonce is rejected as an unexpected field. The existing core idempotency and
simulator execution records remain responsible for preventing a second
financial effect.

Received, accepted, and rejected proposals append audit events to the existing
sequenced, hash-linked, identity-key-signed checkpoint chain. An accepted
event records `authorization: none`; it is supplementary lifecycle evidence,
not an authorization event. The deterministic decision receipt and its ledger
entry remain produced by the existing decision transaction. Intent lifecycle
events are separate appends and do not replace or weaken that atomic decision
evidence.

## Limits

This milestone does not implement MCP, a planner/agent loop, tool execution,
external model providers, semantic prompt-injection detection, or autonomous
money movement. It does not claim that hostile natural-language instructions
can be recognized; they remain untrusted descriptive data and never grant
capability. The supported capability is deliberately limited to proposing one
transaction to the deterministic core.
