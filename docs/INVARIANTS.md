# FIN//GUARD Security Invariants Specification (I1 - I23)

| Invariant | Description | Enforcement Point | Proving Test | Attack Test | Current Status |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **I1** | A transaction is signed at most once. | `signing/gate.py` + `TransactionRepository.compare_and_swap_state` | `test_concurrent_signing_has_exactly_one_cas_winner`, `test_processes_concurrently_sign_one_transaction_exactly_once` | Thread/process signing contention; signing-evidence failure and retry | Proven for concurrent SQLite writers; a privileged whole-database rewrite remains outside this guarantee |
| **I2** | SIGNED requires a policy receipt bound to the transaction and version; its receipt hash is referenced by the DECISION ledger entry. | `signing/gate.py`, `audit/ledger.py` | `test_approved_transaction_completes_bound_decision_approval_sign_execution_chain`, `test_signing_audit_failure_rolls_back_signature_and_state` | `test_execution_rejects_signed_transaction_when_decision_receipt_is_missing`, `test_coordinated_transaction_and_receipt_row_edit_cannot_authorize_new_amount` | Partial (signed checkpoints are explicit/on-demand; entries after the latest checkpoint are not yet covered) |
| **I3** | Decision, approval, signature, and execution refer to the same canonical v2 transaction hash; stale lifecycle versions are rejected. The lifecycle version itself is not in the signature payload. | `decision/engine.py`, `approvals/service.py`, `signing/gate.py`, simulator | `test_approved_transaction_completes_bound_decision_approval_sign_execution_chain`, `test_execution_rejects_stale_signed_lifecycle_version` | Transaction mutation, stale approval, stale signed row version, signature substitution | Partial: lifecycle is checked through CAS plus receipt/approval/signing evidence, not directly signed. Signed checkpoints protect covered prefixes, but same-database truncation to an earlier checkpoint remains possible without an external anchor; lifecycle-envelope binding still requires separate G6 review |
| **I4** | A nonce is consumed at most once; completed exact decision and execution retries return stored results; idempotency-key reuse with different content is rejected. | `decision/engine.py`, unique transaction nonce/idempotency key, unique simulator execution | `test_idempotent_decision_retry_returns_original_result_without_mutating_transaction`, `test_simulator_rejects_replayed_execution`, `test_execution_failure_rolls_back_reloads_and_can_retry`, `test_processes_concurrently_execute_one_transaction_exactly_once` | `test_same_nonce_second_request_is_blocked`, `test_execution_replay_rejects_missing_committed_audit_evidence` | Partial: process-level execution retries are proven; process-level concurrent decision/idempotency races remain untested |
| **I5** | Approver is not requester; identity and approval key are bound by the signed registry; approval is version-bound, expiring, and single-use per approver. | `approvals/service.py`, signed `ActorConfig.public_key` | `test_approved_transaction_completes_bound_decision_approval_sign_execution_chain`, `test_approval_audit_failure_rolls_back_approval_and_state` | `test_approval_rejects_key_not_bound_to_approver_identity`, `test_forged_approved_state_without_approval_signature_cannot_be_signed`, duplicate-approval regression | Partial (approval state and audit rollback are tested; multiple-approver/process race is untested) |
| **I6** | Strict local AI output is proposal data and cannot set actor, source, nonce, signature, policy, decision, or state. The product MCP server is not implemented. | `ai/schemas.py`, `agent/boundary.py` | `test_agent_request_cannot_supply_authoritative_timestamp`, `test_model_cannot_escalate_actor_identity_or_actor_type` | `test_model_cannot_forge_approval_signature_or_decision`, `test_unauthorized_tool_selection_is_rejected_before_any_tool_call` | Proven for the local AI boundary; MCP remains unproven |
| **I7** | Ledger entries are sequence-numbered and hash-linked; a signed checkpoint covers the ledger prefix through its declared sequence. Later entries may remain beyond the latest checkpoint. | `audit/ledger.py` | `test_audit_ledger_append_and_verify_integrity`, checkpoint verification tests | Audit row/checkpoint tampering and truncation tests | Partial: local signed checkpoints are implemented; checkpointing is on-demand and there is no external anchor |
| **I8** | New transaction money is exact; v2 carries integer minor units; actor/policy currencies must match; float inputs cannot enter authoritative paths. | `money.py`, `core/transaction.py`, decision/policy/risk/signing/simulator | Money/property suite, actor/policy currency mismatch tests | NaN/sub-cent/hash-collision regressions, `test_no_float_in_authoritative_money_paths` | Partial (migration fixture passes; operator DB apply/restore and historical artifact verification unverified) |
| **I9** | Any exception in decision or signing paths results in BLOCKED/FAILED (fail-closed). | `decision/engine.py`, `signing/gate.py` | `test_unknown_identity_fails_closed` | `test_malformed_model_output_is_not_security_blocking` | Proven |
| **I10** | A product MCP surface cannot reach signing, approval, key, or policy-mutation code paths. | Not implemented; future `finguard.mcp` | No product MCP tests exist | No product MCP attack suite exists | Unproven (M4 / FG-501 pending) |
| **I11** | Private keys never appear in logs, errors, receipts or exceptions. | `crypto/keystore.py`, `crypto/signing.py` | `test_keystore_generate_and_unlock` | `test_key_leakage_in_error_logs` | Proven |
| **I12** | Decision + nonce claim + approval request (when required) + lifecycle + receipt + ledger entry are atomic; approval, signing, and execution evidence commits with its corresponding state/effect. | `decision/engine.py`, `approvals/service.py`, `signing/gate.py`, `simulator/service.py`; shared SQLAlchemy session and explicit transaction | `test_successful_decision_commits_state_nonce_receipt_and_audit_together`, all decision checkpoints, approval/signing evidence failure-and-retry tests, six execution recovery checkpoints | Decision evidence/pre-commit injection; approval/signing audit failure; execution mutation/evidence/pre-commit injection | Partial: injected-failure rollback, fresh-session reload, exact retry, and process races are proven; abrupt process death during commit remains untested |
| **I13** | Effective authority denies empty source/destination/action grants; agent wildcards deny; trusted non-agent wildcard use is recorded. | `decision/engine.py`, `core/authority.py`, `identity/registry.py` | `test_decision_engine_denies_empty_destination_allowlist`, registry source-list tests, `test_operator_wildcard_authority_is_allowed_and_emits_signal` | `test_agent_cannot_use_wildcard_authority`, `test_decision_engine_rejects_agent_wildcards_and_audits_operator_wildcard` | Partial (AccountRegistry, mixed-script alias resolution, legacy actor migration/report and reviewed override workflow remain absent) |
| **I14** | Balance conservation: sum of simulator balances invariant across executed transfers. | `simulator/service.py` (integer `balance_minor` updates) | `test_only_signed_transaction_can_move_synthetic_money` | `test_simulator_rejects_replayed_execution`, `test_simulator_rechecks_transaction_signature_before_execution` | Partial (representative transfer proven; generated multi-transfer property test pending) |
| **I15** | Execution consumes the exact decision receipt, approval evidence when required, signer identity/signature, and signed transaction version; financial effects, execution row, lifecycle, and audit evidence commit together. An exact replay returns the stored result without another transfer. | `simulator/service.py`, targeted `BEGIN IMMEDIATE`, decision/approval/signing CAS, unique execution record and same-transaction audit append | `test_execution_starts_begin_immediate_before_reading_transaction`, `test_concurrent_execution_moves_funds_exactly_once`, `test_processes_concurrently_execute_one_transaction_exactly_once`, `test_execution_failure_rolls_back_reloads_and_can_retry` | Missing/corrupt evidence, stale signed version, forged approval, cross-transaction signature, post-sign mutation, concurrent execution | Partial: lock ordering, process/thread single-effect, and injected rollback/retry are proven; abrupt process death and external anchoring remain outstanding |
| **I16** | Model output is restricted to strict extraction fields and remains advisory proposal data; unsupported authority or executable fields are rejected. | `ai/schemas.py`, `agent/boundary.py` | `test_agent_security_boundary.py` schema/intent tests | Forged approval/signature/decision, unauthorized tool selection, prompt-injected output | Proven for the local model boundary; no external model is required for tests |
| **I17** | Agent identity, source account, nonce, idempotency key, and transaction timestamp are server-bound or derived; only registered AGENT identities with explicit source grants are accepted. | `AgentSecurityBoundary`, `IdentityRegistry`, deterministic intent creation | `test_non_agent_identity_cannot_initialize_agent_boundary`, `test_source_account_must_be_an_explicit_agent_grant`, `test_agent_request_cannot_supply_authoritative_timestamp` | Caller/model identity, source, or timestamp substitution | Proven for the in-process boundary |
| **I18** | An agent can invoke only the fixed proposal tool/capability; no signing, approval, key, policy-mutation, or execution tool is exposed. | `AgentToolGateway`, `LocalDecisionToolTransport` | `test_gateway_rejects_unauthorized_tool_identity_and_capability_before_dispatch`, `test_agent_cannot_call_execution_directly` | Unauthorized tool/capability selection and direct-execution attempt | Proven for the local adapter; no product MCP server exists |
| **I19** | Tool results are untrusted data; strict schemas and recomputed local transaction, receipt, and audit evidence are required before an observation is returned. | `AgentToolGateway._load_verified_local_decision` | `test_full_agent_request_requires_human_then_signs_executes_and_checkpoints` | `test_indirect_tool_result_instructions_are_rejected_as_untrusted_data`, `test_gateway_recomputes_canonical_hash_from_persisted_transaction_fields` | Proven for the in-process core adapter |
| **I20** | Agent proposals cannot sign or execute; financial authorization remains in the existing decision, human-approval, SigningGate, and simulator paths. | `DecisionEngine`, `ApprovalService`, `SigningGate`, `FinancialSimulator`; boundary stops at proposal | `test_full_agent_request_requires_human_then_signs_executes_and_checkpoints`, `test_agent_state_machine_does_not_transition_to_execution` | Direct execution and missing-approval attempts | Proven for the tested local vertical slice; approval/signing are operator actions outside agent orchestration |
| **I21** | Each agent turn is bounded to one iteration/tool call with request, intent, response, elapsed-time, and optional financial-value limits; in-flight cancellation/timeout returns reconciliation when outcome may be unknown. | `AgentExecutionLimits`, `AgentSecurityBoundary`, `AgentToolGateway` | Timeout, cancellation, budget, and oversized-intent tests in `test_agent_security_boundary.py` | Excessive loop/tool call, oversized request/result, timeout and cancellation | Proven for the in-process boundary; a blocking remote adapter must enforce its own transport-level cancellation and byte limits |
| **I22** | Sequential replay of a persisted request is idempotent; reusing a request ID with changed extracted content is rejected. Retry timestamps reuse the persisted transaction timestamp only for matching server-bound request provenance. | `AgentSecurityBoundary._create_intent`, `DecisionEngine`, transaction idempotency | `test_replaying_the_same_intent_is_idempotent_and_cannot_create_another_decision`, `test_reusing_an_intent_id_with_changed_extraction_fails_closed` | Replay and request-ID content substitution | Proven for sequential local persisted retries; concurrent first-submission decision contention is untested |
| **I23** | The extraction path exposes no key, credential, arbitrary Python/shell, or database-operation capability; model/tool outputs cannot directly invoke those operations. | `LocalAIAnalyzer`, strict extraction schema, proposal-only transport | `test_secret_request_cannot_add_credentials_to_model_output_or_prompt`, `test_agent_cannot_call_execution_directly` | Secret request, direct execution, tool-result poisoning | Proven for the local path; no remote MCP/model server isolation is claimed |
